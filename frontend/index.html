              Area IRIS API behavior Command Center (read-only)
              Message log No messages.log endpoint in /api/admin/v2. Reads only the tail of messages.log inside IRIS through Embedded Python, from a fixed path (Investigation → Message Log).
              Instance identity /info gives product, version, API version, mode and user, but not the instance name, hostname or host platform. Hostname and platform come from fixed Embedded Python probes; the instance name isn’t shown.
              Task state The task list’s Suspended flag reported false for suspended tasks. Task state is taken from /v2/task/info instead.
              Task timing NextScheduled can be text (“Runs After #1:00”), times carry no timezone, and /v2/task/info keeps only the latest run. Times are shown as IRIS reports them and never parsed as dates; Last Runs is labelled as each task’s most recent run, not a history.
              Database info /v2/database-dir/info returns EndFree as “” for read-only databases, not the documented integer. The Database full check reads only IRIS’s Full flag. The Databases page’s info view can fail for those databases.
              API Management /api/mgmnt rejects the /api/admin JWT; only HTTP Basic authentication works. REST route maps are read with Basic authentication, GET only.
              Web application updates PUT /v2/web-app always resets Type to CSP, which would clear a System application’s flag. Web application changes refuse System applications (and /api/admin, /api/mgmnt).
              Alerts The System Dashboard reports alert counts only, not the alert entries. The Dashboard shows the counts; the Message Log shows the underlying warnings and errors.

                    Secondary · Demonstration
                    
            
                    
              ▶
              
                    
                
                    Demo Issue
                    
                
                    Create → Detect → Explain → Resolve → Verify → Restore → Observe
                    
                
                    Two explicit steps. Create Demo Issue intentionally creates a real, reversible IRIS issue for demonstration and stops, leaving the issue active so you can inspect it in Active Issues. Resolve Demo Issue then detects and resolves it through the normal Issue Resolver workflow, which restores the environment. Every change uses the existing operations and is authorized, confirmed, verified and traced.
                    
                
                    
                  
                    Scenario
                    Dismounted database — IPM
                    
                  
                    Create
                    IPM is dismounted (database.dismount) and verified as dismounted, then left dismounted until you resolve it. While it is, the IPM package manager is unavailable. If anything fails before the dismount is verified, IPM is mounted again.
                    
                  
                    Resolve
                    The active issue is detected, IPM is mounted again with database.mount, and the fix is verified. If the fix fails, the issue stays active and you can resolve it again.
                    
                
                    
              
                    
              
                    
                
                
              
                    
            
                    
            
                    Primary only: the Demo Issue is created and resolved on the Primary instance. Select Primary to run it.
                    

            
                    
              
                    
                ⚠
                This intentionally creates a real issue: the IPM database on the connected IRIS instance is dismounted and stays dismounted until you resolve it.

                              Demo Activity
                              
              Safe demo
            
                              
            
          
                              

          
                              
            
                              This runs real, registered operations through the Command Center’s authorization, confirmation, execution and verification framework, restores every temporary change, and records real execution traces. It is not itself a registered operation.
                              
            
                              What will happen
                              
            
                                
              
                              1. Journal setting: PurgeArchived is switched to the opposite value, verified, then restored to its original value and verified.
                                2. 
              
                              2. Web application description: on a safe web application (/csp/user when available; never a System app, /api/admin or /api/mgmnt), the description is temporarily changed, verified, then restored and verified.
                                3. 
              
                              3. Dry runs only: Mount Database and Run Task Now are simulated when a valid candidate exists — nothing is mounted or run. Otherwise they are skipped.
                                4. 
            
                              
            
                              The rehearsal stops at the first failure and always tries to restore anything it changed. Nothing is sent until you confirm.
                              
            
                              
              
              
            
                              

            
                              Create Demo Issue (separate, manual)
                              
            
                              Intentionally creates a real, reversible IRIS issue for demonstration purposes — scenario: Dismounted database — IPM. The issue is then detected and resolved through the normal Issue Resolver workflow, and the environment is restored afterward.
                              
            
                                
              
                              1. Create the demo issue: the IPM database is checked (Dismount dry run and safety rules), then temporarily dismounted.
                                2. 
              
                              2. Detect: the Command Center issue detection reports it as a Command Center Issue.
                                3. 
              
                              3. Fix: the Resolve Issues operation (Mount Database) mounts IPM again, then IPM being mounted and the issue being gone are verified.
                                4. 
            
                              
            
                              Only IPM is touched. If any step fails after the dismount, IPM is mounted again. Never part of the automatic startup rehearsal. Same as Create Demo Issue on the Issue Resolver page.
                              
            
                              
              
            
                              
          
                              

          
                              
            
            Running the rehearsal — each change is verified and restored…
